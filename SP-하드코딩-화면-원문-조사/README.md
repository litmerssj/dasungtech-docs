# SP 하드코딩 화면·원문 조사

## 조사 결론

현재 화면 호출 SP 407개(화면-SP 연결 742행)를 정적 검사한 결과, 후보 탐지 자체는 198개 SP/98개 route에 걸렸다. 이 문서에서는 그중 화면 결과·저장 금액·업무 대상 자체를 바꾸는 우선 조사 목록 50개 SP를 추렸다. 이 숫자는 “설정으로 확정할 값”의 숫자가 아니라, SQL 본문에서 업무 정책처럼 보이는 리터럴을 가진 SP의 숫자다. 나머지 후보는 공통코드·기술 센티널·표시 포맷인지 원문과 담당자 확인이 필요하다.

특히 다음은 하드코딩으로 볼 근거가 명확하다.

- 품목명·규격·제외 품목번호를 `IN (...)`에 직접 열거
- `SP/GP/FP`, 입출고·발주·판매 구분 코드를 `CASE`/`IN`으로 직접 분기
- `본`을 `6000`으로 환산하거나 부가세를 `0.1`로 계산
- 특정 공정명·거래처·주소·전화·업태·세금코드 등을 SQL에 직접 기입
- 월말·조회기간·순위 상한 등 업무 기간/임계값을 직접 기입

반대로 `EXISTS (SELECT 1)`, `@@ROWCOUNT <= 0`, `''/%` 검색 센티널, `AUD='A/U/D'`, 날짜 포맷용 `112/23`은 기본적으로 기술 계약 또는 SQL 제어값으로 분류해 “이관 확정” 목록에서 제외했다.

## 원문 표시 원칙

`02-SP-원문-근거.md`의 코드 블록은 체크인된 원문에서 그대로 복사한 구간이다. 각 항목에는 전체 원문 경로와 고정 커밋을 함께 적었다. 실서버에만 존재하는 SP는 로컬 live snapshot 경로를 적고, 백엔드 저장소에 없는 사실을 명시했다. 샘플 `EXEC`의 고객 데이터처럼 보이는 값은 업무 실행 근거로 사용하지 않고, 런타임 SQL 본문만 조사했다.

## 현재 판정

이 문서의 `하드코딩 후보`는 다음 중 하나로 최종 판정해야 한다.

1. 공통코드/참조 마스터로 이미 관리됨 — 새 설정을 만들지 않고 원천을 연결
2. 업무 설정으로 관리해야 함 — 타입·단위·효력일·승인 이력 필요
3. 코드에 남겨야 하는 기술 계약 — 이관하지 않음
4. 더 이상 사용하지 않는 legacy — 호출 여부와 폐기 근거 확인

코드만으로 업무 담당자·변경 승인자·미래 정책을 확정하지 않는다.
