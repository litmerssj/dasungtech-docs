## 하드코딩으로 포함한 것

다음 조건을 모두 또는 대부분 만족하면 후보로 포함했다.

1. 리터럴이 `WHERE`, `CASE`, `IN`, `NOT IN`, 산술식, 출력 컬럼에 있다.
2. 품목·공정·주문·입출고·재고·금액·세금·마감·AS 분류처럼 업무 결과를 바꾼다.
3. 화면 호출 SP의 실제 런타임 본문에 있다.
4. 공통코드/마스터 조회가 있더라도 조직·시스템·분류 키가 SQL에 직접 고정돼 있거나, 코드 목록 자체를 직접 열거한다.

## 포함하지 않은 것

| 제외 | 이유 |
| --- | --- |
| `EXISTS (SELECT 1)`, `@@ROWCOUNT <= 0` | SQL 실행·오류 검사용 기술 상수 |
| `''`, `%`, `NULL`, `AUD='A/U/D'`, `Y/N` | 검색 센티널·API/SP 계약일 가능성이 높아 업무 설정으로 단정하지 않음 |
| `CONVERT(...,112)`, `CONVERT(...,23)`, 문자열 길이 | 표시 포맷/자료형 계약 |
| `SET NOCOUNT ON`, `TOP 1`, `ORDER BY`의 일반 문법 숫자 | 실행 방법 자체를 바꾸는 기술값 |
| 헤더의 샘플 `EXEC` | 테스트 예시이며 런타임 규칙의 근거가 아님 |
| 비밀번호·암호화 키·토큰 | 보안 비밀로 분류하고 원문값을 복제하지 않음 |

다만 `Y/N`, `04/99`, `02/03`처럼 업무 상태로 쓰인 값은 완전히 제외하지 않고, 목록에서 `코드/업무 규칙 분리 필요`로 표시했다.

## 자동 후보와 사람이 읽는 목록의 관계

화면 호출 SP 전체에 대한 정적 후보 탐지에서는 198개 SP/98개 route가 후보로 걸렸다. 이 숫자에는 공통코드·표시값·기술 상수가 섞일 수 있으므로, 이 문서에는 그중 화면 결과나 저장 금액을 직접 바꾸는 강한 후보를 우선 기록했다. 198개 전체를 “하드코딩 확정”이라고 부르지 않는다.

누락 여부를 점검할 때는 다음 순서로 재현한다.

```text
screen-sp.tsv의 canonical_sp 742행
  → be_anasa/db/procedures/{DB}/{SP}.sql 원문 확인
  → WHERE/CASE/IN/산술 리터럴 추출
  → screen-catalog.tsv의 route/screen_code/display_name 결합
  → 공통코드·품목·공정·회사 마스터 참조 여부 확인
```

## 실서버 뷰 계정으로 재검증할 때

사용자가 제공할 계정은 SQL Server `VIEW DEFINITION`과 메타데이터 조회에 필요한 읽기 권한만 사용한다. 고객 데이터 행을 조회하거나 INSERT/UPDATE/DELETE를 실행하지 않는다.

```sql
-- 데이터베이스별 컨텍스트에서 실행
SELECT DB_NAME() AS database_name,
       o.name AS procedure_name,
       o.modify_date,
       HASHBYTES('SHA2_256', OBJECT_DEFINITION(o.object_id)) AS definition_hash
FROM sys.objects AS o
WHERE o.type = 'P';

SELECT OBJECT_SCHEMA_NAME(object_id) AS schema_name,
       OBJECT_NAME(object_id) AS procedure_name,
       definition
FROM sys.sql_modules
WHERE object_id = OBJECT_ID(N'dbo.대상SP');
```

실제 재수집 시에는 `sys.sql_modules`/`OBJECT_DEFINITION` 결과를 파일로 보관하고, 다음을 비교한다.

- procedure name·database·modify_date
- 원문 정규화 후 SHA-256
- 신규/삭제 SP
- 원문에서 추가·삭제된 업무 리터럴
- `screen-sp.tsv` caller와 운영 객체의 불일치

## 최종 확정에 필요한 확인

- 품목·공정·공구 목록이 마스터 테이블에 이미 존재하는가?
- `SP/GP/FP`, 입출고·발주·판매 구분 코드의 공식 코드표는 무엇인가?
- `本→6000`, VAT `0.1`, 화물비 5백만원 기준, 박스 단가의 소유자와 변경 주기는 무엇인가?
- 특정 거래처/품목/공정 제외가 영구 정책인가, 당시 예외인가?
- 화면 운영자가 변경할 수 있는 범위와 승인·적용일·원복 규칙은 무엇인가?

위 질문의 답이 정해지기 전에는 BAS 설정 테이블이나 API 필드를 확정하지 않는다. 이 문서는 코드에서 확인된 사실과 업무 확인이 필요한 후보를 분리해 둔 상태다.
