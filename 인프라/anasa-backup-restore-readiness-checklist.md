## 7. 장애 시 기본 순서

1. 장애 시각, 사용자 영향과 마지막 정상 시각을 기록한다.
2. API만의 문제인지, SQL/Redis 문제인지, EC2/EBS/AZ 문제인지 분류한다.
3. 원인 확인 전 반복 재시작이나 원본 볼륨 변경을 최소화한다.
4. 데이터 손상 가능성이 있으면 수리 전에 원본 스냅샷 또는 증거를 보존한다.
5. 동일 인스턴스 복구가 승인 RTO를 넘을 것으로 보이면 대체 환경 복원으로 전환한다.
6. DB 복원 후 API 헬스체크만 보지 말고 업무 담당자가 핵심 거래를 검증한다.
7. 복구 시각, 손실 범위, 임시 변경과 후속 조치를 기록한다.
8. 5영업일 이내에 원인·재발방지·실제 RTO/RPO를 검토한다.

| 훈련 | 주기 초안 | 통과 기준 |

| 새 환경 DB 복원 | 월 1회 또는 분기 1회 | 모든 필수 DB 복원·무결성 검사 |
| 전체 ERP 업무 복구 훈련 | 분기 1회 | 승인 RTO/RPO와 핵심 업무 검증 통과 |
