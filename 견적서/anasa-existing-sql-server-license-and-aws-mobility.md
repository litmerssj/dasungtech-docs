# ANASA 기존 SQL Server 라이선스 및 AWS 이전권 확인

| 항목 | 내용 |
| --- | --- |
| 작성일 | 2026-08-28 |
| 목적 | 기존 전산실 SQL Server 권리를 확인해 AWS 운영용 신규 구매 여부 결정 |
| 현재 서버 접속 | 불가 |
| 현재 결론 | 기존 유료 에디션 사용 가능성은 매우 높지만 소유권·AWS 이전권은 미확인 |
| 구매 원칙 | 권리 실사와 Microsoft CSP 서면 확인 전 신규 라이선스 구매 보류 |

## 1. 결론

다성테크는 사내 전산실 서버에서 SQL Server 기반 ERP를 오랫동안 실제 업무에 사용했고, 그 데이터가 현재 ANASA 환경으로 이전됐다. 주요 DB의 데이터 파일 크기가 SQL Server Express의 DB당 10GB 한도를 초과하므로, 원본 DB 크기를 스테이징에서 임의로 확장한 것이 아니라면 기존 운영 인스턴스는 Express가 아니었다고 판단할 수 있다.

정상적인 라이선스 운영이었다면 기존 서버에는 SQL Server Standard 또는 Enterprise 계열의 유료 사용권이 적용됐을 가능성이 매우 높다. 따라서 현재 견적의 신규 Standard 구매는 확정비가 아니라 **기존 권리를 재사용하지 못할 때의 보수적 상한**으로 취급한다.

다만 아래 세 질문은 서로 다르다.

1. 기존 서버가 어떤 SQL Server 에디션으로 운영됐는가?
2. 그 라이선스를 다성테크가 소유하는가?
3. 그 권리로 AWS EC2와 현재 목표 버전인 SQL Server 2022를 운영할 수 있는가?

첫 번째는 강하게 추정할 수 있지만 두 번째와 세 번째는 계약 증빙 없이 확정할 수 없다.

## 2. 확인된 사실과 판단 수준

| 구분 | 내용 | 판단 수준 |
| --- | --- | :---: |
| 업무 사용 | 사내 전산실 SQL Server ERP를 실제 업무에 장기간 사용 | 사용자 확인 |
| 기술 구조 | 기존 ERP와 ANASA는 SQL Server 저장 프로시저와 여러 업무 DB를 사용 | 확인 |
| 데이터 출처 | 현재 ANASA DB는 실제 업무 환경에서 가져온 데이터 | 사용자 확인 |
| 전체 크기 | 접근 가능한 5개 DB 데이터 약 263.41GB, 로그 포함 약 278.72GB | 확인 |
| Express 한도 초과 | MISTO, MISPD, MISTW가 DB당 데이터 10GB 초과 | 확인 |
| 기존 에디션 | Express가 아닌 Standard/Enterprise였을 가능성이 매우 높음 | 강한 추정 |
| 라이선스 존재 | 정상 운영이었다면 유료 운영권이 적용됐을 가능성이 매우 높음 | 강한 추정 |
| 라이선스 소유자 | 다성테크, ERP 공급사 또는 서버 공급사 중 누구인지 | 미확인 |
| 계약 형태 | OEM, 영구, 구독, SPLA, 볼륨 라이선스 등 | 미확인 |
| AWS 이전권 | 기존 권리를 AWS EC2에 반입할 수 있는지 | 미확인 |
| 버전 권리 | 기존 권리로 SQL Server 2022를 실행할 수 있는지 | 미확인 |

## 3. Express가 아니라고 판단하는 근거

| DB | 데이터 | 로그 | 합계 | Express 판단 |
| --- | ---: | ---: | ---: | --- |
| MISTO | 136.33GB | 0.49GB | 136.82GB | 10GB 초과, 불가 |
| MISPD | 107.43GB | 8.61GB | 116.04GB | 10GB 초과, 불가 |
| MISTW | 13.13GB | 1.70GB | 14.83GB | 10GB 초과, 불가 |
| MISSA | 3.29GB | 4.42GB | 7.71GB | 용량만 보면 가능 |
| MISCM | 3.23GB | 0.09GB | 3.32GB | 용량만 보면 가능 |

Express도 저장 프로시저, 트리거와 트랜잭션을 지원한다. 따라서 저장 프로시저의 존재만으로 유료 에디션을 증명할 수는 없다. 여기서는 주요 DB의 데이터 파일 크기가 10GB를 크게 넘는다는 점이 판단 근거다.

이 판단에는 다음 전제가 있다.

- 현재 크기가 실제 전산실 DB 또는 그 백업에서 이어진 크기다.
- 클라우드 복원 후 데이터 파일을 임의로 10GB 이상 확장하지 않았다.
- 측정값은 로그만이 아니라 데이터 파일 크기를 포함한다.

## 4. 사내 전산실에서도 라이선스가 필요한 이유

회사가 물리 서버 장비를 소유하는 것과 SQL Server 소프트웨어 사용권은 별개다.

```text
물리 서버 장비     → 하드웨어 소유
Windows Server     → 운영체제 사용권
SQL Server         → DBMS 사용권
ERP 프로그램       → ERP 계약·사용권
```

SQL Server Standard 또는 Enterprise를 사내 서버에서 실제 운영했다면 그 환경에도 적법한 운영권이 필요했다. AWS로 이전하면서 처음 라이선스가 생기는 것이 아니다. 기존에는 다음과 같이 서버 또는 ERP 계약에 묶여 비용과 권리 주체가 드러나지 않았을 수 있다.

- 서버 구매에 포함된 OEM
- 다성테크 명의 영구 또는 볼륨 라이선스
- ERP 공급사가 제공한 SPLA·임대 라이선스
- 구독 계약 또는 유지보수 계약에 포함된 사용권

## 5. 기존 권리가 있어도 AWS로 못 가져올 수 있는 경우

| 기존 권리 형태 | AWS 재사용 판단 | 주요 확인점 |
| --- | --- | --- |
| OEM | 어려울 가능성이 큼 | 기존 물리 장비 귀속 여부 |
| ERP 업체 SPLA·임대 | 고객의 직접 반입이 어려울 수 있음 | 계약 주체와 계약 종료 시 권리 |
| 다성테크 명의 영구 라이선스 | 가능성 있음 | 구매일, 계약 조건, EC2 테넌시와 이동 권리 |
| 영구 라이선스 + 유효한 Software Assurance | 가능성 비교적 높음 | License Mobility 자격과 신고 절차 |
| Server+CAL | 가능성 있음 | 서버 권리와 모든 사용자·장치 CAL, 이동 조건 |
| SQL Server 2014 영구 권리 | 2022 권리와 별개 | 업그레이드 권리 또는 유효한 SA |

AWS 이전 불가는 데이터를 옮길 수 없다는 의미가 아니다. 기존 사용권을 AWS에서 재사용하지 못해 AWS 라이선스 포함 서비스나 새 구독·영구 권리가 필요하다는 의미다.

## 6. 현재 서버에 접속할 수 없을 때 확인하는 방법

### 6.1 다성테크 내부 자료

- ERP 최초 구축 계약서와 견적서
- 서버·Windows Server·SQL Server 구매명세서와 세금계산서
- Microsoft CSP·총판·리셀러 계약서
- 제품 키, COA, 라이선스 증서와 계약 번호
- Microsoft 볼륨 라이선스 또는 관리 포털의 권리 명세
- 회계 자산대장과 유지보수비 지급 내역
- 기존 전산 담당자, ERP 업체와 서버 공급사의 확인서

제품 키만으로 AWS 이전권이 증명되는 것은 아니다. 라이선스 명세, 구매 주체와 계약 조건을 함께 확보한다.

### 6.2 기존 ERP·전산업체에 요청할 항목

아래 문구를 그대로 전달할 수 있다.

> 다성테크 기존 전산실 ERP 서버에 설치된 Microsoft SQL Server의 에디션·버전, 라이선스 소유자, 계약 방식(OEM/영구/구독/SPLA), 코어 또는 Server+CAL 수량, Software Assurance 유효기간, 구매 증빙과 계약 번호를 제공해 주세요. 해당 권리를 AWS EC2로 이전할 수 있는지, SQL Server 2022 실행 권리가 있는지, 전환 기간 중 기존 서버와 AWS 동시 사용이 가능한지, HA 수동 대기 서버 권리가 있는지도 확인해 주세요.

### 6.3 백업 파일로 확인 가능한 범위

백업 메타데이터로 원본 SQL Server의 버전과 서버명 일부를 확인할 수 있지만, 라이선스 소유자와 AWS 이동 권리를 증명할 수는 없다. DB의 Enterprise 전용 기능 사용 여부도 검사할 수 있으나 이것은 필요한 에디션을 판단하는 기술 증거일 뿐 구매 권리의 증거가 아니다.

## 7. Microsoft CSP 최종 확인 질문

기존 증빙을 확보한 뒤 CSP 또는 Microsoft 라이선스 파트너에게 다음 질문에 대해 서면 답변을 받는다.

1. 계약상 라이선스 소유자는 다성테크인가?
2. 기존 권리는 코어 방식인가, Server+CAL 방식인가?
3. 현재 보유 수량으로 AWS의 4 vCPU DB 서버를 충족하는가?
4. AWS EC2 기본 테넌시 또는 전용 호스트 중 허용되는 배치 방식은 무엇인가?
5. License Mobility와 활성 Software Assurance가 필요한가?
6. 기존 버전 권리로 SQL Server 2022를 실행할 수 있는가?
7. 전산실에서 AWS로 절체하는 기간의 동시 운영이 허용되는가?
8. 앱·DB 전체 HA에서 수동 대기 DB 서버를 추가 라이선스 없이 둘 수 있는가?
9. 컨테이너 기반 SQL Server 운영 시 코어 할당과 최소 라이선스 수량은 어떻게 계산하는가?
10. 필요한 신고서, 제출처와 승인 완료일은 언제인가?

## 8. 결과별 실행안

| 확인 결과 | 실행안 | 비용 영향 |
| --- | --- | --- |
| 기존 적격 권리와 2022·AWS 이전권 확인 | BYOL 적용 후 AWS 배치 | 신규 4코어 구매비 약 1,215만원 감소 가능 |
| 기존 권리는 있으나 2022 업그레이드권 없음 | 허용 버전·지원 위험과 업그레이드 구매 비교 | 별도 견적 필요 |
| OEM 또는 공급사 소유로 이전 불가 | Standard 구독·영구 또는 라이선스 포함 AWS 비교 | 현재 보수적 견적 적용 |
| 증빙을 찾지 못함 | 재사용하지 않고 새 권리 확보 | 감사·컴플라이언스 위험 회피 |
| Server+CAL 적합 | 실제 사용자·장치 수 확정 후 코어 방식과 비교 | 인원이 적으면 절감 가능 |
| RDS 또는 라이선스 포함 EC2 선택 | 시간당 요금에 사용권 포함 | 영구 구매 없음, 반복비 증가 |

## 9. 구매 승인 게이트

다음 항목이 완료되기 전에는 최종 구매 주문을 실행하지 않는다.

- [ ] 기존 ERP 업체와 전산업체에 라이선스 자료 요청
- [ ] 다성테크 회계·계약 자료 검색
- [ ] 기존 에디션·버전·계약 방식 확인
- [ ] 라이선스 소유자가 다성테크인지 확인
- [ ] Software Assurance와 License Mobility 자격 확인
- [ ] SQL Server 2022 사용권 확인
- [ ] AWS EC2 배치 방식과 코어 수량 확인
- [ ] 전환 기간 동시 사용권 확인
- [ ] HA 대기 서버 권리 확인
- [ ] CSP 서면 답변 보관
- [ ] BYOL, 영구 구매, 구독, 라이선스 포함 AWS의 최종 금액 비교
- [ ] 대표이사 또는 비용 승인권자의 최종 승인

## 10. 견적에 미치는 영향

현재 [최종 운영 견적서](./anasa-final-cost-estimate.md)는 기존 라이선스를 재사용할 수 없다고 가정해 SQL Server Standard 4코어 영구 라이선스 약 1,215만원을 첫해 비용에 포함한다.

| 시나리오 | 기본안 첫해 | 2년 차 이후 반복비 |
| --- | ---: | ---: |
| 신규 영구 라이선스 구매 | 약 2,006만원 | 월 약 66만원 |
| 기존 적격 권리 활용, 증분 구매비 0원 가정 | 약 791만원 + 계약·SA 관련 비용 | 월 약 66만원 + 관련 유지비 |

기존 권리를 사용할 수 있더라도 Software Assurance, CSP 계약, 전용 호스트 또는 라이선스 관리 비용이 추가될 수 있으므로 “기존 라이선스 확인 = 완전 무료”로 확정하지 않는다.
